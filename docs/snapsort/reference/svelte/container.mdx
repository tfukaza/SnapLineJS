`Container` groups `Item` components into a sortable region and manages their
drag session. Every container must be rendered inside an `Engine`.

## A Basic Container

We start with a basic to-do list with two items.
A container receives an array through `items`, then uses its `entry`
snippet to render one `Item` for each entry.

<ContainerIntroExample kind="basic" />

Each item needs a stable `id`. By default, `Container` reads that ID from the
entry's `id` property, and the same value is passed to `Item` as `itemId`.

This first example only shows the component structure. Its `todos` array is
fixed, so it does not commit a new order when an item is dropped. The next step
makes the list reorderable with Svelte state.

### Make the List Sortable

Change the array to `$state`, then add an `onItemMove` callback. SnapSort tells
the callback which item moved and its destination index; the callback updates
the array, and Svelte renders the new order.

<ContainerIntroExample kind="sortable" />

Svelte owns the rendered collection, so persistent callbacks such as
`onItemMove` must update state synchronously. The adapter commits that render
before SnapSort measures and animates the final DOM.

### Mix Items and Containers

An `entry` snippet can choose between an `Item` and a nested `Container`. This
lets one ordered collection mix loose items with groups that hold their own
items. The nested container needs its own `itemId` because it is also an entry
in the parent; set `locked={false}` when that entire container should be
movable.

The example remains one SnapSort tree. Its two nested groups use application
metadata and a `canDrop` callback so their tasks can move between them while
the parent rejects task drops into its top-level mixture.

<ContainerIntroExample kind="mixed" />

## Component Properties

### `items`, `getItemId`, and `entry`

`items` is the collection Svelte renders. `entry` renders exactly one `Item` or
nested `Container` for each value. The default `getItemId` reads `entry.id`; pass
your own function when the stable key has another name.

<ContainerPropertyExample kind="collection" />

### `config`

`config` changes the container's sorting behavior. The most prominent
configuration is `direction`, which sets the main layout direction.

<ContainerPropertyExample kind="config" />

The full set of configuration options is listed in [Config](#config).

### `bind:container`

`bind:container` provides the core object when a button, keyboard command,
or other control needs to move an item imperatively. This property lets devs hook
directly into SnapSort's core API and imperatively invoke actions.

In the example below, clicking "Move ->" directly triggers the
callback to move an item. The callback still updates Svelte state synchronously;
`moveItem` requests the move but does not take ownership of the rendered collection.

<ContainerPropertyExample kind="metadata" />

> [!WARNING]
> Containers that need to interact must share one root `Container`. Drop-policy
> callbacks can filter destinations inside that tree; they cannot connect
> otherwise independent roots.

### `itemId`, `locked`, and `selected`

A `Container` can itself be an entry in a parent container. Give that nested
container an `itemId`, then set `locked={false}` to let it drag. `locked` defaults
to `true`, which is safer for containers that only organize child items.

`selected` is a consumer-owned flag. Dragging one selected entry moves the other
selected entries with it; your interface remains responsible for the selection
controls and state.

> [!NOTE]
> As you may have noticed, currently this is a minor bug where
> margins between items being dragged are always 0, regardless
> of the gap or margin in the original layout.

<ContainerPropertyExample kind="nested" />

### `class`, `className`, `style`, and HTML attributes

`Container` renders a `div`, so standard div attributes such as `aria-label` and
`data-*` pass through. Both Svelte's `class` prop and the cross-framework
`className` alias are merged with SnapSort's own classes; `style` is appended to
the layout styles SnapSort needs.

<ContainerPropertyExample kind="presentation" />

## Snippets

### `before` and `after`

These snippets render fixed content around the sortable entries. They are useful
for headings, footers, empty-state controls, or any element that is not a
draggable item.

<ContainerPropertyExample kind="before-after" />

### `ghost`

The `ghost` snippet customizes the framework-owned placeholder used during a
drag. Render the provided event with `Ghost` so SnapSort can bind and size the
placeholder while your markup supplies its content and style.

## Snippet Parameters

Snippet parameters are positional; names such as `entry`, `task`, and `event`
are local names chosen by the application. The Svelte adapter exposes these
contracts:

```ts
type ContainerSnippets<T> = {
  entry: Snippet<[entry: T]>;
  ghost?: Snippet<[event: GhostInsertEvent]>;
  before?: Snippet<[]>;
  after?: Snippet<[]>;
};
```

### `entry(entry)`

The `entry` snippet receives exactly one value from `items`. Its type is the
array's entry type `T`; SnapSort does not wrap it or add fields. `getItemId`
receives the same value and must return the stable ID passed to the rendered
`Item` or nested `Container`.

```svelte
<Container items={tasks} getItemId={(task) => task.key}>
  {#snippet entry(task)}
    <Item itemId={task.key}>{task.label}</Item>
  {/snippet}
</Container>
```

- First parameter (`T`) — the original entry from `items`. Its available
  properties are defined entirely by the application.

The snippet must render one `Item` or nested `Container` for that entry. Its
`itemId` should match `getItemId(entry)`, which defaults to `entry.id`.

### `ghost(event)`

The `ghost` snippet receives a `GhostInsertEvent` for each framework-owned ghost
entry. Always pass the complete event to `<Ghost {event}>`; the component uses
it to bind the ghost's core object and calculate its size and position. A ghost
can represent an entire multi-item drag, so use `items` or `itemIds` when the
interface supports multi-selection.

```ts
type GhostKind = "flow" | "marker";
type GhostRole = "target" | "source" | "pointer";
```

- `kind` (`GhostKind`) — the ghost geometry. `flow` is a full-size layout
  placeholder. `marker` is an insertion marker or swap pointer; inspect `role`
  to distinguish those cases.

- `role` (`GhostRole`) — the ghost's job in the session: `target` destination
  preview, `source` position placeholder, or `pointer` floating visual.

- `container` (`Container`) and `containerMetadata`
  (`Record<string, unknown>`) — the core container currently rendering the
  ghost and its application metadata.

- `index` (`number`) and `beforeElement` (`HTMLElement | null`) — the
  prospective insertion slot and the element after it. The index excludes
  dragged items; pointer ghosts use `-1` because they have no list position.

- `original`, `originalItemId`, and `originalMetadata` — the original `Item`,
  its `ItemId`, and its `ItemSnapshotMetadata` represented by this ghost anchor.

- `items` and `itemIds` — the complete ordered drag run as `Item[]` and
  `ItemId[]`.

- `ghostItem`, `ghostItemId`, and `ghostMetadata` — the temporary core ghost
  object and its identity. `<Ghost>` binds its DOM element to `ghostItem`.

- `ghostRect` (`GhostRect | null | undefined`) — precomputed geometry used for
  sizing and positioning when provided.

- `session` (`DragSession`) — the active drag session, including the pointer,
  source locations, dragged items, and drop effect.

Use `kind` and `role` when different ghost forms need different content:

```svelte
{#snippet ghost(event)}
  <Ghost {event}>
    {#if event.kind === "marker"}
      {event.role === "pointer" ? "Dragging" : "Insert here"}
    {:else}
      Drop {String(event.originalItemId)} here
    {/if}
  </Ghost>
{/snippet}
```

`before` and `after` receive no parameters.

## Config

| Option | Default | Description |
|--------|---------|-------------|
| `mode` | `"euclidean"` | Drag/drop mode for this tree: `"euclidean"`, `"progressive"`, `"insertion"`, or `"swap"`. |
| `direction` | `"column"` | Main layout direction: `"column"` or `"row"`. |
| `mainAxisAlign` | `"start"` | Main-axis alignment for virtual placement. Supports `"start"` and `"center"`. |
| `name` | Generated | Human-readable container name. |
| `animation` | `undefined` | Optional reorder, drop, and click-move animation settings. Omit it or set it to `null` for no animation. |
| `dropPriority` | `0` | Base preference for candidate positions owned directly by this container. Higher eligible priorities are considered first. |
| `callbacks` | No persistent mutation default | Required framework-state callbacks plus lifecycle and validation hooks. |

Animations are opt-in. Use SnapSort's standard 100ms preset when you want the
library's conventional motion:

```svelte
<script lang="ts">
  import { defaultAnimations } from "@snap-engine/snapsort";
</script>

<Container config={{ animation: defaultAnimations }} />
```

Mode is resolved from the root container when a drag starts, so nested containers in one drag tree should use the same mode.

## Callbacks

Callbacks belong to the specific `Container` where they are configured. They
are never inherited by nested containers and never bubble to a parent. The
receiver shown below is the container whose `callbacks` object SnapSort reads;
event fields such as `source`, `from`, `to`, and `current` describe locations
and do not change that receiver.

| Callback | Fires on | Built-in modes / trigger | Notes |
|----------|----------|--------------------------|-------|
| `onItemMove(event)` | Direct destination (`event.to.container`) | Euclidean/progressive move or copy commits; insertion copy or placement-changing moves; placement-changing programmatic `moveItem`; Vanilla's swap fallback | Preferred state callback. It reports one semantic move (or copy insertion) with both `from` and `to`; same-placement insertion/programmatic moves are no-ops, and the source does not also receive `onItemRemove`. |
| `onItemInsert(event)` | Direct destination (`event.container`) | Primitive insertions; otherwise the move, copy, programmatic, and Vanilla swap-fallback paths when that destination has no `onItemMove` | Lower-level destination primitive and fallback. Configure either this callback or `onItemMove` anywhere an item can land. |
| `onItemRemove(event)` | Current direct owner, or transient clone host (`event.container`) | Programmatic `removeItem`; cleanup of an uncommitted euclidean/progressive copy clone | This is not the source half of an ordinary move. Programmatic events have `session === null`; copy cleanup carries its session. |
| `onItemSwap(event)` | Dragged item's pre-swap direct source (`event.a.container`) | Swap commit only | Receives both participants once. The target container does not receive a second swap callback. Current limitation: swap mode does not honor `dropEffect` values `"copy"` or `"none"`; it still follows the swap path. Required by the Svelte adapter. |
| `onDragClone(event)` | Tree root | Euclidean/progressive start with `session.dropEffect === "copy"` | Runs inside the root's mutation transaction. Materialize and bind every `cloneItems` entry synchronously or the copy drag is vetoed. |
| `onDragStart(event)` | Tree root | Start of every mode | Runs directly, outside `flushMutation`. Return `false` to veto; `event.source.container` identifies the direct source. |
| `onDragEnd(event)` | Tree root | End of every activated drag, including cancellation | Runs through the root's `flushMutation` after the final mutation or return path. It does not fire after a startup veto or pre-activation failure. Inspect `event.source` and `event.destination` for locations. |
| `onDropTargetChange(event)` | Tree root | Every mode, when the prospective container or index changes | Runs through the root's `flushMutation`. `event.current?.container` is the prospective target, not the receiver. Flow copy must be chosen in `onDragStart` and must not be toggled here. |
| `onDragItemEnter(event)` | Direct owner of `event.overItem` (`event.container`) | Every mode, when the pointer first enters an item's hitbox | Semantically distinct from resolved slot changes, but hit-testing is scoped to items in the currently resolved target container. Runs directly. |
| `onDragItemMove(event)` | Direct owner of `event.overItem` (`event.container`) | Every mode, on each pointer move while still inside an item's hitbox | Semantically distinct from resolved slot changes, but hit-testing is scoped to items in the currently resolved target container. Runs directly. |
| `onDragItemLeave(event)` | Direct owner of `event.overItem` (`event.container`) | Every mode, when the pointer leaves an item's hitbox or the drag ends | Part of the same target-scoped hover stream; the final leave prevents hover UI from remaining active. Runs directly. |
| `onVisualGeometryInvalidated(event)` | Tree root (`event.root`) | Mode-independent, after transient drag, ghost, animation, or settle geometry changes | Direct notification, including outside an active session; coalesced to at most once per engine frame. |
| `canDrop(event)` | Each candidate destination (`event.container`) | Every mode, once per candidate container during each target resolution | Runs directly before priority. Return `false` to reject all candidates owned directly by that container for this resolution. Programmatic moves bypass it. |
| `getDropPriority(event)` | Each eligible candidate destination (`event.container`) | Every mode, once per eligible container during each target resolution | Runs directly after `canDrop`. Return a finite override or `undefined` to keep `dropPriority`. Programmatic moves bypass it. |
| `createGhost(event)` | Container where the ghost is first created (`event.container`) | Flow move/none: initial source; flow copy: first valid destination; insertion: first valid destination; swap: root | Creation hook only; moving an existing ghost does not fire it again. Svelte supplies it internally because it owns ghost DOM. Consumer configuration is unsupported; customize the `ghost` snippet instead. Runs directly. |
| `onGhostInsert(event)` | Current ghost owner (`event.container`) | Flow source/destination placement; insertion target placement; swap root pointer placement and movement | Svelte updates its internal ghost collection through that owner's `flushMutation`, then invokes the consumer callback as an optional notification. |
| `onGhostRemove(event)` | Ghost owner it is leaving (`event.container`) | Ghost crosses containers, is replaced, or the session ends | Svelte removes its internal ghost entry through the departing owner's `flushMutation`, then invokes the consumer callback as an optional notification. |
| `flushMutation(mutation)` | Same container as the callback being transacted | Structural and lifecycle mutations in every mode, plus programmatic mutations | Adapter hook, not a session event. Svelte supplies it automatically. It wraps item move/insert/remove/swap, ghost insert/remove, and root drag clone, target-change, and drag-end callbacks. |
| `awaitMutation()` | Same receiver, only when `flushMutation` is absent | Deprecated compatibility path after a mutation | Svelte supplies `flushMutation`, so this fallback is not used. Promise results cannot provide a paint-atomic commit. |

The table describes **dispatch**, which is separate from startup
**configuration validation**. For framework-owned trees, SnapSort verifies
that the source can service mutations before activating a drag even though a
successful move is later dispatched on the destination.

- In euclidean, progressive, and insertion trees, configure either
  `onItemMove` or `onItemInsert` on every possible direct source and
  destination.
- Configure `onItemSwap` on every container that can be the direct source of a
  swap.
- Svelte supplies `createGhost`, `onGhostInsert`, and `onGhostRemove` on every
  `Container`; consumer ghost callbacks are optional notifications after its
  internal ghost state changes.
- A shared handler object is fine, but pass it explicitly to every
  participating `Container`; nesting alone does not share callbacks.

Configure `onItemRemove` as well when a container can receive
`removeItem(id)` or can host a transient flow-copy clone. Ordinary moves emit
only the destination-owned `onItemMove`/`onItemInsert` event.

Update Svelte arrays synchronously in `onItemMove` or `onItemSwap`. The adapter
uses `flushSync`, allowing SnapSort to read final DOM geometry before paint.
Missing callbacks fail clearly instead of mutating framework-rendered DOM.

### Drop policy events

Drop targeting follows eligibility, priority, then the selected placement
mode. `CanDropEvent` includes `itemMetadata`/`itemsMetadata`, destination
`containerMetadata`, the primary `source`, and `sources` parallel to the full
multi-item drag. `DropPriorityEvent` adds `staticPriority`, pointer and frozen
rectangle geometry, and destination depth. Priority applies only to candidates
owned directly by this container and does not propagate to nested containers.

See [Drop Policies](/docs/snapsort/guides/04_drop_policies) for metadata-driven
grouping, exact resolution rules, and reusable callbacks from
`@snap-engine/snapsort/callbacks`.

## Core Object API

After capturing the object with `bind:container`, these are the most commonly
used core properties and methods.

| API | Description |
|-----|-------------|
| `container.moveItem(id, targetContainer, index)` | Authoritatively moves an item into another container or index, bypassing drop eligibility and priority. |
| `container.removeItem(id)` | Removes an item by `itemId` or internal object ID. |
| `container.numberOfItems` | Number of tracked child items. |
| `container.dropPriority` | Gets or sets the container's base candidate priority. |
| `container.direction` | Gets or sets `"column"` or `"row"`. |
| `container.mainAxisAlign` | Gets or sets `"start"` or `"center"`. |
| `container.mode` | Gets or sets the drag/drop mode. |
| `container.config` | Live `ContainerConfig` object. |
| `container.callbacks` | Configured callback object. |
| `container.dragSession` | Active `DragSession`, or `null`. |
