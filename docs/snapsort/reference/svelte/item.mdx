`Item` connects one rendered entry to a SnapSort `Container`. Every item must
be rendered beneath an `Engine` and a `Container` so it can join that
container's drag tree. In normal application code, omit the `item` prop: the
component creates, configures, and eventually destroys its own core Item.

## A Basic Item

Render an `Item` from each ordinary entry in the application-owned keyed loop,
give it `entry.itemId`, and put the entry's content inside the component. When
`onItemMove` updates the render tree or another application collection, Svelte
reconciles the new order.

<ItemExample kind="basic" />

`Item` renders a `div` with the `snapsort-item` class, writes its immutable ID to
`data-snapsort-item-id`, and provides its core Item object to descendants such
as `Handle`.

Adding or deleting an ordinary application value is an application-state
operation. When its keyed `Item` mounts or unmounts, the wrapper synchronizes
the core registration; that reconciliation does not emit `onItemInsert` or
`onItemRemove`. Those callbacks report core-originated commands instead.

## Component Properties

The Svelte component accepts the following SnapSort-specific properties in
addition to standard `HTMLDivElement` attributes and events:

```ts
type ItemProps = Omit<HTMLAttributes<HTMLDivElement>, "children"> & {
  children: Snippet;
  className?: string;
  item?: SnapSortItem | null;
  itemId: string;
  metadata?: ItemMetadata;
  selected?: boolean;
};
```

### `children`

`children` is the required Svelte snippet rendered inside the Item's `div`.
SnapSort does not impose a content structure, so an item can contain text,
cards, form controls, or other components.

```svelte
<Item itemId={task.id}>
  <strong>{task.title}</strong>
  <span>{task.assignee}</span>
</Item>
```

### `itemId`

`itemId` is the stable application identity used by move and remove commands,
ghosts, keyed collection updates, and callback events. It is required for both
component-owned and adopted Items, must be non-empty, and cannot change while
the component remains mounted.

```svelte
<Item itemId={task.id}>{task.title}</Item>
```

When using `createRenderEntry` or `createRenderEntries`, pass the same ID to
the helper and the rendered `Item`. Do not put the ID in `metadata`:
`metadata.itemId` is unsupported and throws a clear error.

### `metadata`

`metadata` is a read-only open record for application data that SnapSort should carry
alongside the Item. It appears as `itemMetadata` and `itemsMetadata` in drag,
mutation, hover, eligibility, and priority callbacks, and is frozen into the
Item's drag snapshot.

The example attaches an owner and priority to each Item. Dragging a card shows
the metadata received by the container callbacks.

<ItemExample kind="metadata" />

`ItemMetadata` is `Readonly<Record<string, unknown>>`. The application may
replace the metadata object; Svelte synchronizes the replacement to the core
Item, while an active drag keeps its shallow frozen snapshot. SnapSort never
mutates the object supplied by the application.

Geometry is deliberately not metadata. An insertion-marker `GhostState`
contains SnapSort's canonical gap and adjacent frozen Item geometry; render it
through `Ghost` or convert it with `insertionMarkerRect`. Customize item
hover/swap hitboxes with the candidate owner's `getItemHitbox` callback.

### `selected` and DOM events

`selected` is a consumer-owned boolean. SnapSort does not render selection
controls or selected styling. When a drag starts on a selected Item, all other
selected Items in the same drag tree join it; dragging an unselected Item moves
only that Item.

Standard events such as `onclick` and `onkeydown` pass through to the rendered
`div`, so they can update the application's selection state. Add the matching
keyboard behavior and ARIA state when the Item itself acts as a control.

### `bind:item`

Use `bind:item` when application controls need to inspect or call the core Item.
The binding receives the same automatically created instance that SnapSort uses
internally; it does not change the component's ownership of that instance.

```svelte
<script lang="ts">
  import type { Item as SnapSortItem } from "@snap-engine/snapsort";

  let item = $state<SnapSortItem | null>(null);
</script>

<Item itemId={task.id} bind:item>{task.title}</Item>

<button type="button" onclick={() => item?.container.moveItem(task.id, archive, 0)}>
  Move to archive
</button>
```

### `item` (advanced)

Passing a non-null `item` adopts that exact core instance instead of creating a
new one. This is an advanced integration seam: most Item components should
omit it and use `bind:item` when they only need access to the generated object.

For an application-created instance, construct it with the same Engine and
surrounding core Container, passing `{ itemId }` to its constructor. The
component's required `itemId` prop must match that construction-time identity.
The adapter binds its rendered element but does not reparent or destroy the
instance. Omitted `metadata` and `selected` props preserve existing values;
explicitly supplied props override them. Neither the instance nor its identity
can change after mount, and the creating code remains responsible for cleanup.

<ItemExample kind="item-instance" />

An adopted Item can also participate in an advanced
`DragSession.handoff(replacements)` integration. The application must create
and mount the exact replacement instance before handoff, and remains
responsible for its data and lifetime. Handoff retargets the pending gesture
during `onDragStart`; lifecycle activation locks it afterward. It does not make
the instance a copy or perform framework cleanup. Ordinary copy interfaces do
not need adopted Items—use a normal `onItemMove` state update that moves the
original record and creates a fresh replacement record at its source.

### `class`, `className`, `style`, and HTML attributes

`Item` renders a regular `div`. Svelte's native `class` and the cross-framework
`className` alias are merged with `snapsort-item`; `style`, ARIA attributes,
`data-*` attributes, and other div properties pass through.

```svelte
<Item
  itemId={task.id}
  class:urgent={task.priority === "high"}
  className="task-card"
  style="--task-accent: tomato;"
  aria-label={`Task: ${task.title}`}
  data-priority={task.priority}
>
  {task.title}
</Item>
```

SnapSort owns the final `data-snapsort-item-id` value. Use your own `data-*`
name for additional application state.

## Handle

`Handle` makes a descendant element the Item's drag input. Once it mounts, a
drag can begin from the Handle instead of the rest of the Item, leaving nearby
buttons, links, and inputs available for their ordinary interactions.

<ItemExample kind="handle" />

The component accepts standard `HTMLDivElement` attributes plus these aliases:

```ts
type HandleProps = Omit<HTMLAttributes<HTMLDivElement>, "children"> & {
  children: Snippet;
  className?: string;
};
```

### `children`

The required snippet supplies the visible grip, label, icon, or other handle
content. `Handle` renders it inside a `div` and registers that element with the
nearest Item through Svelte context.

### Presentation and HTML attributes

Native `class`, `className`, `style`, ARIA attributes, and other div properties
are forwarded just like Item properties. The rendered element always includes
`snapsort-handle`.

Use one Handle per Item. The core object has one input-alias slot, so a later
Handle replaces the earlier drag target rather than creating multiple handles.
