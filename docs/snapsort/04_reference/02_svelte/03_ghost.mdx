`Ghost` renders temporary SnapSort-owned visual state inside a Svelte
collection. The application owns the RenderTree and DOM projection, while
SnapSort owns when each ghost appears, moves, and disappears.

Import the component from the Svelte binding and its state helpers from the
framework-neutral package:

```svelte
<script lang="ts">
  import { Ghost } from "@snap-engine/snapsort/svelte";
  import type { GhostState } from "@snap-engine/snapsort";

  let { ghost }: { ghost: GhostState } = $props();
</script>

<Ghost {ghost} />
```

## Component Properties

```ts
type GhostProps = Omit<HTMLAttributes<HTMLDivElement>, "children"> & {
  ghost: GhostState;
  children?: Snippet;
  className?: string;
  insertionMarker?: InsertionMarkerRectOptions;
};
```

| Prop              | Default                                        | Description                                                                 |
| ----------------- | ---------------------------------------------- | --------------------------------------------------------------------------- |
| `ghost`           | Required                                       | Immutable lifecycle state supplied by a ghost callback or RenderTree entry. |
| `children`        | Empty                                          | Optional custom content rendered inside the ghost element.                  |
| `className`       | `""`                                           | Cross-framework class alias merged with `class` and `snapsort-ghost`.       |
| `insertionMarker` | `{ thickness: 3, startInset: 0, endInset: 0 }` | Presentation used only for an insertion marker.                             |

The component renders a `div`. Standard Svelte div attributes, including
`class`, `style`, ARIA attributes, and `data-*`, pass through. Consumer styles
are appended after SnapSort's calculated structural styles, so use them for
intentional visual overrides without changing the supplied ghost state.

## RenderTree Integration

Ghost lifecycle callbacks update framework state synchronously. Render the
resulting ghost entry in the same keyed sequence as ordinary Items and nested
Containers:

```svelte
<script lang="ts">
  import {
    reduceRenderTree,
    type ContainerCallbacks,
    type GhostLifecycleEvent,
  } from "@snap-engine/snapsort";
  import { Ghost, Item } from "@snap-engine/snapsort/svelte";

  function applyGhostEvent(event: GhostLifecycleEvent) {
    tree = reduceRenderTree(tree, event);
  }

  const callbacks = {
    onGhostInsert: applyGhostEvent,
    onGhostMove: applyGhostEvent,
    onGhostRemove: applyGhostEvent,
  } satisfies ContainerCallbacks;
</script>

{#each tree.entries as entry (entry.itemId)}
  {#if entry.isGhost}
    <Ghost ghost={entry.ghost} />
  {:else}
    <Item itemId={entry.itemId}>{entry.value.label}</Item>
  {/if}
{/each}
```

Use `entry.itemId` as the key. For a ghost entry it is the generated,
root-unique `ghostItemId`. Do not derive a key from the original application
Item or the array index.

Framework callbacks must update framework state and let Svelte reconcile the
DOM. Do not call `insertBefore`, `appendChild`, `remove`, or another structural
DOM API for a Svelte-rendered ghost.

## Ghost Roles

`GhostState` is a closed discriminated union. Test `ghost.type` when a role
needs different content or styling.

| `ghost.type`       | Meaning                                                         | Geometry and location                                           |
| ------------------ | --------------------------------------------------------------- | --------------------------------------------------------------- |
| `source-spacer`    | Preserves a vacated source slot when the real Item is hoisted.  | `rect` and a slot `location` with `container` and `index`.      |
| `target-spacer`    | Reserves the prospective flow-layout destination.               | `rect` and a slot `location` with `container` and `index`.      |
| `insertion-marker` | Paints the resolved gap used by insertion placement.            | `gap`, neighbors, current-placement state, and a slot location. |
| `pointer-preview`  | Represents the dragged run in an overlay following the pointer. | `rect` and an overlay `location` without an index.              |

Pointer representation and placement feedback are independent. A session can,
for example, own both a `pointer-preview` and an `insertion-marker` at the same
time. `onGhostMove` reports structural relocation or changed marker
presentation; it is not a continuous pointer-move stream.

## Shared Identity and Provenance

Every role carries the same base state:

```ts
interface GhostStateBase {
  readonly session: DragSession;
  readonly original: Item;
  readonly originalItemId: ItemId;
  readonly originalMetadata: ItemMetadata;
  readonly items: readonly Item[];
  readonly itemIds: readonly ItemId[];
  readonly ghostItem: Item;
  readonly ghostItemId: ItemId;
  readonly ghostMetadata: ItemMetadata;
}
```

`original` identifies the ordinary Item represented by this ghost anchor,
while `items` describes the complete ordered dragged run. `ghostItem` is an
already-created transient core Item. `Ghost` binds its rendered element to
that object when mounted, updates the binding if the ghost object changes, and
detaches it on unmount. Never render the same state through `Item` or persist a
ghost as application data.

## Positioning Behavior

Source and target spacers remain in the collection's normal flow. `Ghost`
applies their measured width, height, and original Item margins so they occupy
the intended slot.

Pointer previews and insertion markers are overlays. `Ghost` positions them
absolutely in their owning Container's local coordinate space, disables
pointer events, and assigns the overlay z-index. A pointer preview converts its
world-space `rect` with `toContainerLocalRect`.

An insertion marker instead expands SnapSort's zero-thickness world-space
`gap` with `insertionMarkerRect`. Customize that painted rectangle explicitly:

```svelte
<Ghost
  ghost={entry.ghost}
  insertionMarker={{ thickness: 4, startInset: 8, endInset: 8 }}
/>
```

The insets mean left/right for a horizontal gap and top/bottom for a vertical
gap. They affect presentation only and never feed back into drop-target
ranking. Each value must be finite and non-negative, and the two insets must
not exceed `ghost.gap.length` when added together.

## DOM Contract

The rendered element always includes:

- `snapsort-ghost`
- `data-snapsort-ghost-entry={ghost.type}`
- `data-snapsort-ghost-item-count={ghost.items.length}`

Pointer previews additionally use `data-snapsort-ghost="pointer"`; insertion
markers use `data-snapsort-ghost="insertion"`. The default `id` is `spacer`,
and callers may override it through ordinary attributes.

For the callback lifecycle that creates and removes these entries, continue to
[Drags and Ghosts](/docs/snapsort/guides/sessions/ghosts). See
[DragSession](/docs/snapsort/reference/drag-session) for the independent
`dragVisual` control.
