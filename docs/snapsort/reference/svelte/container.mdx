`Container` groups `Item` components into a sortable region and manages their
drag session. Every container must be rendered inside an `Engine`.

## A Basic Container

We start with a basic to-do list with two items.
A container receives an array through `items`, then uses its `entry`
snippet to render one `Item` for each entry.

<ContainerIntroExample kind="basic" />

Each item needs a stable `id`. By default, `Container` reads that ID from the
entry's `id` property, and the same value is passed to `Item` as `itemId`.

This first example only shows the component structure. Its `todos` array is
fixed, so it does not commit a new order when an item is dropped. The next step
makes the list reorderable with Svelte state.

### Make the List Sortable

Change the array to `$state`, then add an `onItemMove` callback. SnapSort tells
the callback which item moved and its destination index; the callback updates
the array, and Svelte renders the new order.

<ContainerIntroExample kind="sortable" />

Svelte owns the rendered collection, so persistent callbacks such as
`onItemMove` must update state synchronously. The adapter commits that render
before SnapSort measures and animates the final DOM.

### Mix Items and Containers

An `entry` snippet can choose between an `Item` and a nested `Container`. This
lets one ordered collection mix loose items with groups that hold their own
items. The nested container needs its own `itemId` because it is also an entry
in the parent; set `locked={false}` when that entire container should be
movable.

The example remains one SnapSort tree. Its two nested groups share a `groupID`,
so their tasks can move between them, while the parent uses a separate group for
its top-level mixture of items and containers.

<ContainerIntroExample kind="mixed" />

## Component Properties

### `items`, `getItemId`, and `entry`

`items` is the collection Svelte renders. `entry` renders exactly one `Item` or
nested `Container` for each value. The default `getItemId` reads `entry.id`; pass
your own function when the stable key has another name.

<ContainerPropertyExample kind="collection" />

### `config`

`config` changes the container's sorting behavior. The most prominent
configuration is `direction`, which sets the main layout direction.

<ContainerPropertyExample kind="config" />

The full set of configuration options is listed in [Config](#config).

### `bind:container`

`bind:container` provides the core object when a button, keyboard command,
or other control needs to move an item imperatively. This property lets devs hook
directly into SnapSort's core API and imperatively invoke actions.

In the example below, clicking "Move ->" directly triggers the
callback to move an item. The callback still updates Svelte state synchronously;
`moveItem` requests the move but does not take ownership of the rendered collection.

<ContainerPropertyExample kind="metadata" />

> [!WARNING]
> Containers that need to interact must share one root `Container`. A matching
> `groupID` filters compatible destinations inside that tree; it does not connect
> otherwise independent roots.

### `itemId`, `locked`, and `selected`

A `Container` can itself be an entry in a parent container. Give that nested
container an `itemId`, then set `locked={false}` to let it drag. `locked` defaults
to `true`, which is safer for containers that only organize child items.

`selected` is a consumer-owned flag. Dragging one selected entry moves the other
selected entries with it; your interface remains responsible for the selection
controls and state.

> [!NOTE]
> As you may have noticed, currently this is a minor bug where
> margins between items being dragged are always 0, regardless
> of the gap or margin in the original layout.

<ContainerPropertyExample kind="nested" />

### `class`, `className`, `style`, and HTML attributes

`Container` renders a `div`, so standard div attributes such as `aria-label` and
`data-*` pass through. Both Svelte's `class` prop and the cross-framework
`className` alias are merged with SnapSort's own classes; `style` is appended to
the layout styles SnapSort needs.

<ContainerPropertyExample kind="presentation" />

## Snippets

### `before` and `after`

These snippets render fixed content around the sortable entries. They are useful
for headings, footers, empty-state controls, or any element that is not a
draggable item.

<ContainerPropertyExample kind="before-after" />

### `ghost`

The `ghost` snippet customizes the framework-owned placeholder used during a
drag. Render the provided event with `Ghost` so SnapSort can bind and size the
placeholder while your markup supplies its content and style.

<ContainerPropertyExample kind="ghost" />



## Snippet Parameters

Snippet parameters are positional; names such as `entry`, `task`, and `event`
are local names chosen by the application. The Svelte adapter exposes these
contracts:

```ts
type ContainerSnippets<T> = {
  entry: Snippet<[entry: T]>;
  ghost?: Snippet<[event: GhostInsertEvent]>;
  before?: Snippet<[]>;
  after?: Snippet<[]>;
};
```

### `entry(entry)`

The `entry` snippet receives exactly one value from `items`. Its type is the
array's entry type `T`; SnapSort does not wrap it or add fields. `getItemId`
receives the same value and must return the stable ID passed to the rendered
`Item` or nested `Container`.

```svelte
<Container items={tasks} getItemId={(task) => task.key}>
  {#snippet entry(task)}
    <Item itemId={task.key}>{task.label}</Item>
  {/snippet}
</Container>
```

- First parameter (`T`) — the original entry from `items`. Its available
  properties are defined entirely by the application.

The snippet must render one `Item` or nested `Container` for that entry. Its
`itemId` should match `getItemId(entry)`, which defaults to `entry.id`.

### `ghost(event)`

The `ghost` snippet receives a `GhostInsertEvent` for each framework-owned ghost
entry. Always pass the complete event to `<Ghost {event}>`; the component uses
it to bind the ghost's core object and calculate its size and position. A ghost
can represent an entire multi-item drag, so use `items` or `itemIds` when the
interface supports multi-selection.

```ts
type GhostKind = "flow" | "marker";
type GhostRole = "target" | "source" | "pointer";
```

- `kind` (`GhostKind`) — the ghost geometry. `flow` is a full-size layout
  placeholder. `marker` is an insertion marker or swap pointer; inspect `role`
  to distinguish those cases.

- `role` (`GhostRole`) — the ghost's job in the session: `target` destination
  preview, `source` position placeholder, or `pointer` floating visual.

- `container` (`Container`) and `containerMetadata`
  (`Record<string, unknown>`) — the core container currently rendering the
  ghost and its application metadata.

- `index` (`number`) and `beforeElement` (`HTMLElement | null`) — the
  prospective insertion slot and the element after it. The index excludes
  dragged items; pointer ghosts use `-1` because they have no list position.

- `original`, `originalItemId`, and `originalMetadata` — the original `Item`,
  its `ItemId`, and its `ItemSnapshotMetadata` represented by this ghost anchor.

- `items` and `itemIds` — the complete ordered drag run as `Item[]` and
  `ItemId[]`.

- `ghostItem`, `ghostItemId`, and `ghostMetadata` — the temporary core ghost
  object and its identity. `<Ghost>` binds its DOM element to `ghostItem`.

- `ghostRect` (`GhostRect | null | undefined`) — precomputed geometry used for
  sizing and positioning when provided.

- `session` (`DragSession`) — the active drag session, including the pointer,
  source locations, dragged items, and drop effect.

Use `kind` and `role` when different ghost forms need different content:

```svelte
{#snippet ghost(event)}
  <Ghost {event}>
    {#if event.kind === "marker"}
      {event.role === "pointer" ? "Dragging" : "Insert here"}
    {:else}
      Drop {String(event.originalItemId)} here
    {/if}
  </Ghost>
{/snippet}
```

`before` and `after` receive no parameters.

## Config

| Option | Default | Description |
|--------|---------|-------------|
| `mode` | `"euclidean"` | Drag/drop mode for this tree: `"euclidean"`, `"progressive"`, `"insertion"`, or `"swap"`. |
| `strategy` | Resolved from `mode` | Advanced custom `{ dropTarget, lifecycle }` strategy pair that overrides `mode`. |
| `direction` | `"column"` | Main layout direction: `"column"` or `"row"`. |
| `groupID` | `"default-group"` | Within one root tree, containers with the same group can exchange items. |
| `mainAxisAlign` | `"start"` | Main-axis alignment for virtual placement. Supports `"start"` and `"center"`. |
| `name` | Generated | Human-readable container name. |
| `animation` | Default 100ms animations | Reorder, drop, and click-move animation settings. Set to `null` to disable configured animations. |
| `disableFlip` | `false` | Disables FLIP movement animation. |
| `noDrop` | `false` | Prevents the container from being a drop target. Useful for root layout containers. |
| `dropArea` | `false` | Treats the container as an explicit drop area for collision filtering. |
| `callbacks` | No persistent mutation default | Required framework-state callbacks plus lifecycle and validation hooks. |

Mode is resolved from the root container when a drag starts, so nested containers in one drag tree should use the same mode.

## Callbacks

| Callback | When it runs |
|----------|--------------|
| `onItemMove(event)` | An item moves to a new container or index. Preferred for state-backed lists because it includes both `from` and `to`. |
| `onItemSwap(event)` | Swap mode commits a pairwise slot exchange. Required for swap mode in the Svelte adapter. |
| `onItemInsert(event)` | An item is inserted into a container; this is the lower-level fallback for `onItemMove`. |
| `onItemRemove(event)` | An item is removed through `removeItem(id)`. |
| `onDragStart(event)` | A drag is starting. Return `false` to veto it. |
| `onDragEnd(event)` | A drag has ended and its mutation has committed. |
| `onDropTargetChange(event)` | The prospective drop container or index changed. Fires on the root container. |
| `canDrop(event)` | Resolves whether this container accepts the current drag. Keep it cheap. |
| `onGhostInsert(event)` | Optional notification after the Svelte adapter inserts or moves its framework-owned ghost entry. |
| `onGhostRemove(event)` | Optional notification after the Svelte adapter removes its framework-owned ghost entry. |
| `createGhost(event)` | Core/Vanilla hook. Unsupported by the Svelte adapter; customize framework-owned ghosts with the `ghost` snippet. |
| `flushMutation(mutation)` | Runs a structural callback inside the adapter's synchronous Svelte commit. Supplied automatically. |
| `awaitMutation()` | Deprecated compatibility callback. |

Update Svelte arrays synchronously in `onItemMove` or `onItemSwap`. The adapter
uses `flushSync`, allowing SnapSort to read final DOM geometry before paint.
Missing callbacks fail clearly instead of mutating framework-rendered DOM.

## Core Object API

After capturing the object with `bind:container`, these are the most commonly
used core properties and methods.

| API | Description |
|-----|-------------|
| `container.moveItem(id, targetContainer, index)` | Moves an item into another container or index. |
| `container.removeItem(id)` | Removes an item by `itemId` or internal object ID. |
| `container.numberOfItems` | Number of tracked child items. |
| `container.groupID` | Configured group ID. |
| `container.direction` | Gets or sets `"column"` or `"row"`. |
| `container.mainAxisAlign` | Gets or sets `"start"` or `"center"`. |
| `container.dropArea` | Gets or sets explicit drop-area behavior. |
| `container.mode` | Gets or sets the drag/drop mode. |
| `container.config` | Live `ContainerConfig` object. |
| `container.callbacks` | Configured callback object. |
| `container.dragSession` | Active `DragSession`, or `null`. |
