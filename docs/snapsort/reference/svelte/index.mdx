The Svelte binding wraps SnapSort's core objects in Svelte 5 components. Use it when Svelte owns the DOM and your component state remains the source of truth for item order.

## Install

```bash
npm install @snap-engine/snapsort @snap-engine/asset-base
```

For SvelteKit, bundle the raw TypeScript asset packages during SSR:

```javascript
// vite.config.js
import { sveltekit } from "@sveltejs/kit/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [sveltekit()],
  ssr: {
    noExternal: ["@snap-engine/asset-base", "@snap-engine/snapsort"],
  },
});
```

## Import

```svelte
<script lang="ts">
  import { Engine } from "@snap-engine/asset-base/svelte";
  import { Container, Ghost, Handle, Item } from "@snap-engine/snapsort/svelte";
</script>
```

Wrap the sortable tree in an `Engine`, then compose containers and items:

Here `tasks` is a `$state` array and `onItemMove` synchronously reorders it by
stable item ID. See the Container page for the complete handler.

```svelte
<Engine id="tasks">
  <Container
    config={{ direction: "column", groupID: "tasks", callbacks: { onItemMove } }}
    items={tasks}
    getItemId={(task) => task.id}
  >
    {#snippet entry(task)}
      <Item itemId={task.id}>
        <Handle className="drag-handle">Drag</Handle>
        {task.label}
      </Item>
    {/snippet}
  </Container>
</Engine>
```

## Components

- [Container](/docs/snapsort/reference/svelte/container) — props, modes, callbacks, custom ghosts, and the bindable core API.
- [Item](/docs/snapsort/reference/svelte/item) — props, identity, metadata, selection, and drag handles.

`Ghost` is used inside a `Container`'s custom `ghost` snippet. `Handle` belongs inside an `Item` and limits where a drag can begin.

Every wrapper forwards standard `div` attributes. Both Svelte's `class` prop
and the legacy `className` alias are accepted, and consumer `style` values are
appended after the structural defaults.

The supported component subpaths are exactly `Container.svelte`, `Item.svelte`,
`Ghost.svelte`, and `Handle.svelte`. Placement behavior is selected with
`config.mode`; there are no mode-specific component exports.

## Core Types

Import callback events, configuration, metadata, and bindable object types from the framework-agnostic package:

```ts
import type {
  CanDropEvent,
  Container as SnapSortContainer,
  ContainerCallbacks,
  ContainerConfig,
  DragEndEvent,
  DragStartEvent,
  ItemMoveEvent,
  ItemSnapshotMetadata,
  ItemSwapEvent,
} from "@snap-engine/snapsort";
```

For the application-state pattern shared by both adapters, see [Session Lifecycle](/docs/snapsort/guides/03_session_lifecycle).
